# Backup and recovery

The application uses SQLite and file-backed subtitle artifacts. Discover the live database/data paths from the Pi service environment before scheduling backups; never infer them from the checkout.

Use `npm run catalog:backup -- <destination-directory>` or SQLite's online backup API while the database is live. The command writes a timestamped directory using SQLite online backup, copies the configured `SUBTITLE_DATA_DIR` immutable assets, refuses symlinks, computes SHA-256 hashes, checks SQLite integrity and foreign keys, checks that every subtitle artifact/asset path referenced by the database is in the backup, rejects extra unmanifested files, and verifies the staging snapshot before publishing it. The manifest records the absolute original asset root because some DB rows contain absolute asset paths. Restore assets under that same path before starting services; relocation requires a reviewed DB path-rewrite tool, which is not included. A filesystem copy of a live WAL database without its WAL files is not a valid backup. Copy an encrypted second copy off the Pi and keep retention bounded by disk budget. The command does not configure a schedule or retention policy.

Monthly restore drill: copy the backup to a separate recovery directory and run `npm run catalog:backup -- --verify <recovery-directory>`, then open its `catalog.db` read-only and confirm title/episode/job/artifact counts and a sample subtitle file. The automated test suite creates a temporary SQLite backup, opens the snapshot as a restored DB, and verifies its subtitle file; this does not count as a Pi/off-device restore drill. Never test restoration over the live database. Before schema changes, create and verify a backup; record the migration version with it.

Recovery order: stop writers, preserve a copy of current database and logs, restore the selected backup and matching asset tree to a new directory, validate integrity and permissions, point the service at it, start the API, then start background workers. Preserve the failed state for diagnosis until recovery is confirmed.
