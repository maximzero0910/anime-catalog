# Reliability work progress

Date: 2026-11-17. Branch: `production-hardening`.

## Phase A — discovery

Architecture and baseline are documented in [RELIABILITY_AUDIT.md](./RELIABILITY_AUDIT.md). The working tree contained substantial pre-existing changes; they were preserved. No Pi, Cloudflare, secret, production DB, or deployment state was changed.

## Phase B — implemented changes

- All SQLite catalog readers and writers now derive their path from the same `CATALOG_DB_PATH` resolver; a temporary-path test covers the contract.
- Added no-store liveness and local-catalog readiness routes. Readiness fails closed without returning filesystem/database errors.
- Added persisted heartbeats for subtitle, subtitle-index, and Telegram workers and heartbeat status to authenticated admin APIs. A crashed worker ages to stale; a heartbeat write failure logs a sanitized event and does not crash useful work.
- Added an expiring SQLite owner lease around Telegram sync. Concurrent processes cannot both scan; crashed leases expire after 120 seconds, and startup only recovers a stale `syncing` state when no live lease exists.
- Added bounded active/waiting gates for provider search/resolution, AniList metadata, and catalog filter enrichment; queued waiters have a 3-second ceiling and observe request cancellation before acquiring a slot.
- Replaced HLS proxy's 20 ms polling wait loop with a bounded FIFO waiter queue that removes cancelled clients immediately and honors the configured concurrency ceiling when granting slots.
- Made per-process API gate limits environment-configurable with hard clamps; active/waiting counts are visible in authenticated subtitle admin diagnostics.
- Added a bounded response-header wait and browser-abort propagation to the Pages-to-backend proxy; response bodies remain streamed for long media routes.
- Added bounded streamed JSON body parsing to mutation/catalog routes.
- Bounded subtitle provider HTTP cache/miss retention and operational log rows; active jobs, dead letters, and artifacts remain preserved.
- Replaced growing provider caches with capped TTL/LRU caches, evicted failed OpenSubtitles batch promises, and bounded subtitle-index host slots and wait queues.
- Added per-process global and endpoint token buckets for dynamic API routes. Pages strips identity headers and signs its ingress IP; the backend accepts it only from a trusted socket CIDR with a valid, fresh HMAC. `X-Forwarded-For` and raw backend `CF-Connecting-IP` are never used. Bucket storage is capped and idle entries expire.
- Added a 45-second media-readiness deadline to playback loading, a retry action, and teardown of HLS/native media on terminal playback errors. Subtitle requests now have 8-second timeouts, a 30-minute total polling ceiling, and a user retry control after failure. Production build/type-check pass; browser behavior remains unverified here.
- Added a manual online SQLite backup command that checks integrity/foreign keys, copies immutable subtitle assets without following symlinks, writes streaming SHA-256 hashes, verifies every database-referenced subtitle body is present, rejects unmanifested files, and validates staging before publishing the backup directory. It does not schedule backups or perform a production restore.
- Subtitle body writes now use unique synced temporary files followed by atomic rename; content-addressed hits are hashed before reuse, corruption is rejected, and reads validate lexical and resolved paths stay inside the asset directory.
- Subtitle ZIP extraction now limits archives to 500 entries, 8 MiB per expanded subtitle, and 32 MiB combined expansion; malformed and oversized archives cannot trigger unbounded inflate allocation.
- Subtitle normalization now caps source files at 8 MiB, each episode at 20,000 cues, and a cue at 8,192 characters before constructing/processing the full cue set.
- Indexed subtitle delivery goes through the same guarded reader and validates the asset SHA-256 and recorded byte length before a track can be returned; a missing body remains a re-indexable miss, while corrupt data raises an integrity error.
- The Cloudflare Worker resolver JSON path now has timeout, cancellation, response-size and redirect limits. Existing HLS/Range behavior retains its tests.
- Subtitle indexer file downloads now use the HLS proxy's DNS-pinned fetch transport with exact per-provider host rules, validated redirects, a 32 MiB body ceiling, and the shared concurrency bound. Legacy HTTP is enabled only for the exact `subs.sab.bz` host; it still undergoes public-DNS validation and every redirect is revalidated. The general provider JSON/feed requests remain on their existing provider transport.
- Cloudflare Worker HLS manifest bodies now stream through the 1 MiB cap instead of calling `arrayBuffer()` before checking size. Failed manifests retain their upstream status, malformed playlist bodies are rejected, and error bodies are canceled instead of logged in full.
- Subtitle and index job claims now use SQLite `BEGIN IMMEDIATE` transactions so concurrent worker processes serialize selection and cannot both return the same queued rows.
- A subprocess regression test starts eight independent Node processes against one temporary SQLite database and proves translation and index claims each return six unique jobs with no duplicate IDs.
- Telegram synchronization now persists its checkpoint every 25 messages and at completion; replaying the tail after a crash remains idempotent on message IDs.
- GramJS connection, authorization, channel lookup, sync-page, media-message lookup, and video-chunk operations now have a configurable 30-second default deadline (clamped 5–120 seconds). Timed-out calls disconnect their client so a later request can reconnect; media and background synchronization use separate client instances so a stalled catalog scan does not directly interrupt active playback. SIGINT/SIGTERM aborts the sync page wait, releases its lease, and retains the latest checkpoint.
- Telegram playback now leases one of a bounded set of per-stream MTProto clients (default two, hard maximum four), with a bounded wait queue. A stalled/cancelled media RPC invalidates only its slot and reconnects it before reuse; other concurrent streams keep their own clients. Saturation returns 503 with `Retry-After` and does not count as a broken media reference. The authenticated Telegram admin page reports active/capacity/queued stream slots.
- Subtitle worker shutdown preserves the persistent `stopping` control, marks its heartbeat stopped, clears timers, and lets Node exit naturally. It no longer resets operator stop state or writes an invalid zero-timestamp running heartbeat.
- Claimed subtitle discovery and subtitle-index jobs now refresh their SQLite leases during long provider calls. A test verifies index work refreshed within the stale window is retained, then recovered after the refreshed lease expires.
- Stale subtitle and subtitle-index jobs now enforce retry ceilings during crash recovery. Jobs at the ceiling become terminal `FAILED` entries rather than returning to the runnable queue; translation jobs are added to the dead-letter table in the same SQLite transaction. Regressions cover both worker types.
- Subtitle indexer caches a provider miss only after a successful empty search. Temporary provider, parse, or asset-storage errors now use the durable index-job backoff instead of poisoning the seven-day negative cache; retry skips only candidate IDs already persisted, allowing a partially completed provider batch to resume. OpenSubtitles without an API key is explicitly disabled and is not interpreted as a no-results response. When a previously disabled provider becomes enabled, its stale miss entries are cleared and affected completed/failed episode jobs are requeued once in the same transaction.
- Per-job lease refresh timers now catch SQLite errors and emit a bounded warning at most once every five minutes, so a transient heartbeat write failure does not become an uncaught timer exception or log storm.
- Optional GPU telemetry in the authenticated subtitle admin endpoint is cached for 60 seconds, including the no-GPU result; simultaneous dashboard requests share one probe instead of spawning `nvidia-smi` repeatedly on CPU-only Pi deployments.
- The same admin endpoint now reports filesystem total/available bytes and used percentage via `statfs`, with a null fallback when the host does not expose the metric; the existing admin dashboard displays disk use and free GiB without exposing filesystem paths.
- Prepared proposed systemd units for the Astro API, subtitle worker, and Telegram sync worker. They use bounded restart bursts, loopback API binding, restricted writable paths, and conservative per-process memory/CPU/task ceilings. Added an allowlisted ten-minute recovery timer so a repeated crash that exhausts systemd's start burst does not remain failed indefinitely; a mocked shell test verifies that only failed Anineko units are reset and started. These are templates only; no Pi service was installed or changed. Paths and ceilings require review against the real Pi mount layout, systemd/cgroup support, and measured workload.

## Remaining work and risks

- **NOT VERIFIED:** the local E2E suite with its Worker/API services running; sustained Pi resource ceilings; filesystem exhaustion recovery; and a production/off-device backup restore. Production search and playback in Chromium, the Pi ARM64 clean build and systemd restart behavior, current Tunnel routing, live health checks, and a manual recovery-service run were verified on 2026-11-17.
- **NOT IMPLEMENTED:** cross-process rate/concurrency limits, automated backup scheduling/retention/off-site encryption, host-level resource alerting, comprehensive frontend recovery coverage, database-corruption recovery runbook automation.
- Worker DNS resolution is not pin-able at connection time using the current Cloudflare Worker fetch API; existing explicit host policy does not prove rebinding resistance there.
- The provider interface does not carry abort signals into every running upstream request; concurrency remains occupied until those operations settle, but cancellation cannot forcibly stop all providers.
- A fresh 2026-11-17 audit reports 11 high-severity dependency paths through picomatch (GHSA-fc5q-39xc-vjpf); no patched version is published yet, and the forced Astro downgrade suggested by npm was not applied.
- The hardened file-download path uses ordinary Undici rather than the previous automatic Impit retry after a 403, because Impit's connection path cannot use the DNS-pinned dispatcher. SAB.BZ download compatibility should be checked against the live provider before relying on that host; broadening the transport without connection-time destination pinning would reintroduce rebinding risk.
- Telegram sync and playback use separate roles; playback clients are slot-isolated but share the same configured StringSession. Concurrent real playback, Telegram's behavior for the multiple connections, and Pi throughput/connection budgets have not been exercised against the live account.
- A read-only census of the current catalog's indexed source URLs found only `anima-pr.blogspot.com`, `raw.githubusercontent.com`, `subs.sab.bz`, and `subsunacs.net`; no OpenSubtitles file URL was present, so its exact `dl.opensubtitles.com` delivery hostname is configured from the provider contract but not confirmed from a stored live response.

## Status

The codebase has useful local recovery controls, and the 2026-11-17 release verified the Pages-to-Pi path, browser search/playback, Pi service restart, and database integrity. The broader reliability mission definition of done is still **not met**: automated/off-device backups and restore, sustained capacity behavior, some failure simulations, cross-process limits, and host-level alerting remain unimplemented or unverified. Four local E2E checks also remain blocked by unavailable services on ports 8787 and 3000; they are not counted as passing.

- 2026-11-17 follow-up: removed the local inference adapter, model probes, model environment options, and the unproductive subtitlestranslator adapter. The translation worker now accepts only the four completed online providers. Existing stored translations were intentionally retained.
- 2026-11-17 backup follow-up: added a free-space preflight, stale staging cleanup, bounded retention, and a daily systemd backup template with a release-aware runner. Backup tests and local snapshot verification pass; a Pi snapshot was verified read-only. The timer is not installed, and off-device restore remains unverified.
